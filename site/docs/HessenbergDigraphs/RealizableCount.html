    The calculator's class count certifies the matrix-realizable support count #

    This file is the bridge that makes the apex classification theorem load-bearing for the executable calculator. On its own, the calculator's output countClasses n (run by the #hessenberg_count command) is only certified against the combinatorial object D_n(S). Here it is connected to the matrix side: the support digraphs realizable by unreduced Givens products are exactly the combinatorial models D_n(S), and up to isomorphism they number countClasses n.

    The proof routes through all three components of classification:

    • digraph_model and completeness identify the realizable supports with { D_n(S) : S : ActiveSet n } (realizableSupports_eq_range);
    • rigid — via card_isoClasses_quot / isoInvariant_eq_iff, the same route as countClasses_eq_isoQuot — certifies the iso-class count.

    Main results #

    • realizableSupports_eq_range — the realizable support digraphs are exactly { D_n(S) : S } (the matrix-side content of classification).
    • realizable_classCount — packaged certificate tying the executable countClasses n to the matrix-realizable support count.

    References #

    Severini, "Digraphs of Real Orthogonal Upper Hessenberg Matrices" — Theorem 1, Theorem 12.

      Mathematical layer — strengthening to the genuine matrix class. #

      The previous results speak of supports of canonical Givens products. We
now lift them to the supports of *all* unreduced orthogonal upper
Hessenberg matrices, using the universality theorem
`OrthogonalHessenberg.exists_givensFactorization` and the fact that sign
equivalence preserves the support pattern.
